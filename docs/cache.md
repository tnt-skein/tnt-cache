# Кэш

Ответ, который считается дорого и меняется редко, — список ролей узла,
карточка клиента, страница о приложении — не должен считаться на каждый
запрос. Пакет `tnt-cache` даёт таким ответам общее место: значение
по ключу на срок. Драйверов три: в памяти процесса, в спейсе Tarantool
и в Redis.

```lua
local store = require('tnt.cache').new({ driver = 'memory', prefix = 'demo:', ttl = 60 })

local roles = store:remember('roles', 300, function() return compute() end)
```

## Зачем пакет

Кэш — не источник правды, и от этого зависит всё его устройство:
читающему промах безопасен, он пересчитает значение сам, а пишущему —
нет, потерянную запись не заметит никто. Поэтому договор отказа назван
у каждого действия: чтение при отказе драйвера отвечает промахом
и пишет о нём в журнал, запись бросает, чистка отдаёт пару `nil, err`
(ниже, «Договор отказа»). Срок, приставку, «положить, если нет»,
счётчик, теги и замок хранилище считает один раз на всех драйверов,
а драйвер знает только, как прочитать, записать и стереть.

Два дела рядом со значением у кэша тоже свои. Правка одного документа
должна сбрасывать все страницы раздела, где он виден, — для этого
у записи есть **теги**, и забывание тега стирает только свои записи,
не обходя остальной кэш. А промах на дорогом ключе не должен запускать
один и тот же пересчёт в каждом из ста пришедших разом запросов — для
этого есть **замок на ключ** и `remember` с замком: считает один,
остальные ждут.

Зависимости: [`tnt-must`](https://github.com/tnt-skein/tnt-must)
(броски ошибок программиста), [`tnt-clock`](https://github.com/tnt-skein/tnt-clock)
(часы срока и ожидания), [`tnt-log`](https://github.com/tnt-skein/tnt-log)
(журнал промахов), [`tnt-metrics`](https://github.com/tnt-skein/tnt-metrics)
(ряды обращений) и [`tnt-external`](https://github.com/tnt-skein/tnt-external)
(подмена часов, уступки и транзакции в проверках). Клиент Redis —
[`tnt-redis`](https://github.com/tnt-skein/tnt-redis) — приходит
аргументом, и пакет его зависимостью не объявляет: кэшу в памяти
и в спейсе он не нужен.

## Как пользоваться

```lua
local cache = require('tnt.cache')

local store = cache.new({ driver = 'memory', prefix = 'demo:', ttl = 60 })

store:put('customers:7', customer, 300)          -- на 300 секунд
store:get('customers:7')                          -- либо nil
store:get('customers:7', {})                      -- либо умолчание
store:has('customers:7')
store:remember('roles', 60, function() return compute() end)
store:add('lock', true, 10)                       -- только если нет
store:pull('token')                               -- взять и забыть
store:forget('customers:7')
store:increment('hits')                           -- прибавить: 1
store:decrement('hits', 2)                        -- убавить: -1
store:flush()                                     -- всё, с чужими приставками
store:sweep()                                     -- стереть просроченное заранее: { swept, scanned } либо nil, err

store:tags({ 'docs' }):put('docs:7', page, 300)   -- запись с тегом
store:tags({ 'docs' }):flush()                    -- забыть все записи тега: сколько стёрто
store:remember('docs:index', 300, render, { lock = 30 })  -- считает один, прочие ждут
store:lock('reports', 30, { wait = 5 })           -- замок на ключ: lock либо nil, err
```

Срок — секунды; пусто — навсегда либо `ttl` из настроек. Просроченное
читается как отсутствующее и стирается по дороге пишущим узлом: сторож
не нужен, а память под мёртвые записи держится не дольше, чем до первого
обращения. `increment` срок записи не продлевает. Как отказывает каждое
действие — ниже, «Договор отказа».

### Чистка заранее

`sweep()` обходит записи кусками — по `chunk` ключей (1000), с уступкой
перед каждым куском, — и просроченное из куска стирает одной партией:
у спейса это одна транзакция вместо своей на каждый ключ. Так обход
спейса на сотни тысяч записей не упирается в срез файбера, а соседние
файберы получают управление между кусками. Уступка обрывает транзакцию
memtx, поэтому внутри транзакции `sweep` не зовут — это ошибка
программиста, и она бросает сразу.

Отчёт — `{ swept, scanned }` либо `nil, err`, если box отказал посреди
обхода: реплика, снесённый спейс. Стёртое до отказа остаётся стёртым —
обход не транзакция. Кому важно не задерживать вызывающего, задаёт
бюджет: `budget` — сколько ключей просмотреть за вызов; кончился —
в отчёте `cursor`, и следующий вызов продолжает с него:

```lua
local report, err = store:sweep({ budget = 5000 })

while report ~= nil and report.cursor ~= nil do
    report, err = store:sweep({ budget = 5000, cursor = report.cursor })
end
```

Курсор значит «бюджет кончился», а не «ключи остались»: обход,
кончившийся ровно на бюджете, вправе отдать курсор, и следующий вызов
вернёт пустой отчёт без него. Часы читаются на каждый кусок: запись,
чей срок вышел, пока обход стоял на уступке, стирается этим же обходом.
Обход — не снимок, и что видно из дописанного и стёртого соседями,
у драйверов разное (ниже).

### Теги

Тег — пометка записи, а не часть её ключа. `store:tags(теги)` отдаёт вид
хранилища: что положено через его `put`, `add` и `remember`, помечено
этими тегами, а `flush` вида забывает все записи с любым из них. Читают
по ключу у самого хранилища — запись с тегом видна `get` и без него.
Пример прогнан на 3.8, вывод — как напечатал прогон:

```lua
local store = cache.new({ driver = 'memory', prefix = 'demo:' })
local docs = store:tags({ 'docs' })

docs:put('docs:1', 'Установка', 300)
store:tags({ 'docs', 'lists' }):put('docs:index', { 'Установка', 'Настройка' })
store:tags('news'):put('news:1', 'Вышел выпуск 3.8')

store:get('docs:1')                                --> Установка
docs:flush()                                       --> 2
store:get('docs:index')                            --> nil
store:get('news:1')                                --> Вышел выпуск 3.8
store:tags('lists'):flush()                        --> 0
```

- **Тег — строка либо список строк**; повторы отбрасываются. Пустое,
  нестроковое и пустой список — ошибка программиста.
- **Теги — с приставкой хранилища**: `flush` тега одного хранилища
  не трогает записи соседа с другой приставкой на том же драйвере.
- **Перезапись заменяет теги.** Запись, положенная без тега поверх
  помеченной, из тега уходит; `increment` и `decrement` теги записи
  держат, как и её срок. У `redis` это не так — ниже, «Драйвер redis».
- **Забывание идёт кусками по тысяче записей, с уступкой перед каждым**,
  как `sweep`: тег на сотни тысяч записей не упирается в срез файбера
  и не держит соседние файберы. Поэтому внутри транзакции box его
  не зовут — это ошибка программиста. Забывают после фиксации правки:
  забытое до неё успел бы посчитать заново сосед — по прежним данным.
- **Отказ драйвера посреди забывания бросает**, как всякая запись:
  тег, забытый наполовину, оставил бы устаревшее значение жить до срока.
  Стёртое до отказа остаётся стёртым.
- **Где держать указатель «тег → ключи», решает драйвер**, и обходить
  весь кэш не приходится ни одному: у `memory` — таблица рядом
  с записями, у `space` — спейс тегов, у `redis` — множество ключей
  на тег. Подробности — у драйверов ниже.

### Замок на ключ

`store:lock(ключ, срок, { wait })` берёт замок и отдаёт его либо
`nil, err`, если замок занят и за `wait` секунд не освободился; без
`wait` — одна попытка. Снимает замок `lock:release()` — только свой:
`true` — снят, `false` — уже не наш (срок вышел, и его стёр либо взял
другой). Пример прогнан на 3.8:

```lua
local lock, err = store:lock('reports', 30)
lock.key                                           --> reports
store:lock('reports', 30)                          --> nil, кэш: замок reports занят
store:lock('reports', 30, { wait = 0.2 })          --> nil, кэш: замок reports занят (через 0.2 с)
lock:release()                                     --> true
lock:release()                                     --> false
store:lock('reports', 30):release()                --> true
```

- **Замок — запись кэша со сроком и меткой держателя.** Срок обязателен:
  замок, брошенный упавшим держателем, иначе не освободился бы никогда.
  Метка — случайный UUID, и держатель, чей срок вышел, замок соседа,
  взятый после, не снимет. Лежит замок под `<приставка>\0lock:<ключ>`:
  нулевой байт в ключах приложения не встречается, и замок не спутать
  со значением того же ключа.
- **Взятие — `add`**, то есть одно действие у драйвера по сети (`SET NX`)
  и вставка у спейса. Отказ драйвера бросает: промах значил бы «замок
  свободен».
- **Ожидающий спрашивает снова раз в 50 мс** (`cache.store.POLL`) и не дольше
  `wait`; последний сон — остаток до срока. Опрос, а не побудка: держатель
  бывает на другом узле, и сказать ожидающему о снятии ему нечем.
- **Ожидание внутри транзакции box — ошибка программиста**: пауза уступает
  управление и оборвала бы транзакцию. Без ожидания (`wait = 0`) замок
  у `memory` и `space` берут и в транзакции — взятие одна запись.
- **Замок не повторный.** Держатель, взявший замок ключа снова, — тот же
  `lock` либо `remember` с `{ lock }` того же ключа, — ждёт сам себя до
  `wait` и получает отказ: метка у каждого взятия своя.

### Посчитать один раз

`remember` с настройками `{ lock, wait }` защищает дорогой ключ от наплыва
при промахе: промах берёт замок ключа на `lock` секунд, взявший считает
и кладёт значение, а остальные ждут — спрашивают кэш раз в 50 мс, пока
значение не появится, но не дольше `wait` (по умолчанию — срок замка).
Пример прогнан на 3.8: десять файберов разом, счёт один.

```lua
local calls = 0

local function render()
    calls = calls + 1
    fiber.sleep(0.1)                               -- дорогой счёт

    return 'оглавление'
end

for _ = 1, 10 do
    fiber.create(function()
        store:remember('docs:toc', 300, render, { lock = 5 })
    end)
end

fiber.sleep(0.3)
calls                                              --> 1

store:lock('docs:slow', 5)                         -- сосед взял замок и считает
store:remember('docs:slow', 300, render, { lock = 0.1 })
--> nil, кэш: docs:slow считает сосед — значения не дождались за 0.1 с
```

- **Взявший читает кэш ещё раз уже под замком**: сосед мог досчитать
  и снять замок между его промахом и взятием, и без второго чтения
  значение считалось бы дважды.
- **Держатель ушёл без значения** — счёт бросил, узел упал — замок берёт
  следующий ожидающий и считает сам: снятый замок либо его вышедший
  срок отпускают очередь.
- **Поломка счёта уходит как есть, но после снятия замка** — ожидающим
  не ждать его срока.
- **Не дождались — `nil, err`, а не бросок**: так бывает, и решать,
  отдать ли пользователю ошибку или посчитать самому, вызывающему.
- **Настройки проверяются и при попадании** — ошибка программиста
  бросает всегда, а не на первом промахе. Внутри транзакции box — только
  с `wait = 0`, как у замка.
- Вид с тегами умеет то же: `store:tags('docs'):remember(ключ, срок,
  счёт, { lock = 5 })` считает один раз и помечает посчитанное.

### Настройки

`cache.new(настройки)` собирает хранилище; негодная настройка —
ошибка программиста, и она бросает сразу.

| Настройка | Что задаёт |
|---|---|
| `name` | имя хранилища в рядах метрик; по умолчанию — имя драйвера |
| `driver` | `memory` (по умолчанию), `space`, `redis` либо свой драйвер — таблицей |
| `prefix` | приставка ключей; по умолчанию пусто |
| `ttl` | срок по умолчанию, секунды; пусто — навсегда |
| `space` | имя спейса либо сам спейс — для `space`; по умолчанию `app_cache` |
| `redis` | клиент `tnt-redis` — для `redis` |
| `namespace` | пространство ключей в Redis — для `redis`; по умолчанию `cache:` |
| `now` | стенные часы — для проверок |

`store:status()` отдаёт то, что настроено, — `{ name, driver, prefix, ttl }`,
без значений.

### Ряды метрик

Промах кэша — не отказ: вызывающий пересчитает значение и никуда
об этом не напишет. Но доля промахов, выросшая за ночь, — это срок,
который кончается раньше, чем значение успевают спросить, или ключ,
в который попала метка времени, а отказ драйвера на чтении виден только
записью журнала, где повторы подавлены. Поэтому каждое обращение
за значением ложится в ряды реестра встроенного `metrics`
([`tnt-metrics`](https://github.com/tnt-skein/tnt-metrics), «Прикладные ряды»):

| Ряд | Род | Метки | Что значит |
|---|---|---|---|
| `cache_requests_total` | counter | `store`, `outcome`: `hit`, `miss`, `failed` | сколько обращений за значением: попадание, промах, отказ драйвера |
| `cache_request_duration_seconds` | histogram | `store` | сколько шло чтение драйвером |

- **Обращение — это `get`, `has`, `pull` и `remember`**, с тегами и с
  замком тоже. Считается оно один раз, по первому чтению: повторное
  чтение под замком и опрос ожидающих — часть того же обращения, и
  двадцать опросов в секунду на ожидающего говорили бы о замке, а не
  о кэше. Ожидающий, дождавшийся значения соседа, — промах: сам он его
  не нашёл.
- **Просроченное — промах**, как и отсутствующее. `failed` — промах
  по отказу драйвера, тот, о котором пишет журнал (ниже, «Договор
  отказа»): вызывающему он такой же промах, а в ряду — своё слово.
- **Запись в ряды не идёт.** `put`, `forget`, `flush`, замок и забывание
  тега при отказе бросают, и вызывающий узнаёт о нём сам; `sweep` отдаёт
  отчёт. `add` и `increment` тоже читают, но это условие записи, а не
  вопрос к кэшу.
- **Длительность — чтение драйвером**, вместе с сетью до Redis
  и стиранием просроченного по дороге, монотонными часами, у отказа тоже.
  Корзины — от 100 мкс до секунды: в памяти процесса чтение идёт
  микросекунды, по сети до Redis — около миллисекунды.
- **Хранилище в метке — по имени** `name` из настроек, а без него —
  по имени драйвера: `memory`, `space`, `redis` либо `name` своего
  драйвера. Не по приставке: приставка бывает пустой и бывает собрана
  из имени узла. Два хранилища на одном драйвере без имён ложатся в одну
  строку ряда; кому нужна разбивка, даёт им имена. Потолок — сто
  хранилищ: их заводит код, и больше сотни на узле — уже ошибка в коде.

```lua
local pages = cache.new({ name = 'pages', prefix = 'page:', ttl = 300 })
local sessions = cache.new({ name = 'sessions', prefix = 'sess:' })

pages:remember('about', 300, render)        -- промах: страница посчитана
pages:remember('about', 300, render)        -- попадание
pages:get('contacts')                       -- промах
sessions:has('a1b2')                        -- промах
```

Выкладка узла после этих четырёх обращений (строки `_bucket` опущены;
порядок рядов и меток у плагина произвольный). Чтение в памяти процесса
заняло микросекунды — все четыре легли в первую корзину:

```
# HELP cache_request_duration_seconds Сколько шло обращение к кэшу за значением: чтение драйвером
# TYPE cache_request_duration_seconds histogram
cache_request_duration_seconds_sum{store="pages"} 3.8280850276351e-06
cache_request_duration_seconds_count{store="pages"} 3
cache_request_duration_seconds_sum{store="sessions"} 3.6600977182388e-07
cache_request_duration_seconds_count{store="sessions"} 1
# HELP cache_requests_total Сколько обращений к кэшу за значением: по хранилищу и итогу — попадание, промах, отказ
# TYPE cache_requests_total counter
cache_requests_total{outcome="hit",store="pages"} 1
cache_requests_total{outcome="miss",store="pages"} 2
cache_requests_total{outcome="miss",store="sessions"} 1
```

Имя — непустая строка. Хранилище без него — ни в настройках, ни у своего
драйвера — ошибка программиста и бросает при заведении, а не на первом
чтении, где метке не нашлось бы значения:

```lua
cache.new({ name = '' })
--> кэш: имя хранилища — непустая строка: name в настройках либо name драйвера
```

## Договор отказа

Хранилище отказывает одним из трёх способов, и какой где — сказано
здесь, а не выясняется в бою:

| Действие | Отказ хранилища или драйвера |
|---|---|
| `get`, `has` | промах: умолчание и `false`, а о причине — запись в журнале |
| `remember` | промах на чтении — значение считается заново; сохранение бросает |
| `pull` | промах на чтении: умолчание, и стирать нечего — значение цело; у `redis` — см. ниже |
| `put`, `forget`, `flush` | бросает |
| `add`, `increment`, `decrement` | бросает, в том числе на чтении |
| `sweep` | `nil, err`, если box отказал посреди обхода |
| `tags(…):put`, `add`, `flush` | бросает; стёртое до отказа остаётся стёртым |
| `tags(…):remember` | как `remember` |
| `lock` | бросает; занят и не освободился за `wait` — `nil, err` |
| `lock:release()` | бросает; замок уже не наш — `false` |
| `remember` с `{ lock }` | бросает на замке; не дождались значения — `nil, err` |

Читающему промах безопасен: кэш — не источник правды, и вызывающий
пересчитает значение сам. Пишущему — нет: потерянную запись не заметит
никто, поэтому отказ записи наружу и выходит. Бросает и чтение, от
которого зависит запись: промах у `add` означал бы «значения нет, пиши
поверх чужого» — а `add` берут замком, — у `increment` и `decrement` —
«считай чужой счётчик с нуля».

О промахе по отказу драйвера остаётся запись в журнале `tnt.cache`
уровнем `warn` — с именем драйвера и причиной. Вот она из прогона на 3.8,
где спейс кэша снесли у драйвера под ногами (заголовок ядра опущен):

```
W> кэш: драйвер space отказал на чтении — промах driver=space err="No index #0 is defined in space 'app_cache'"
```

Подряд идущие повторы подавляются (`log.changes` из
[`tnt-log`](https://github.com/tnt-skein/tnt-log)): драйвер, потерявший
связь, отказывает на каждом чтении, и запись на каждый промах утопила
бы журнал. Пишется первая запись серии, а сколько их было — полем
`suppressed` в той, что серию прервала.
Ключа в записи нет нарочно: он у каждого промаха свой, и серия с ним
не сложилась бы никогда, а вид отказа один на всех.

Ошибка программиста отказом не считается и бросает всегда: пустой или
нестроковый ключ, `put` с пустым значением, срок и шаг прибавки
не числом, негодные настройки `sweep`, негодные теги и теги у драйвера,
который их не знает, срок замка не конечным числом больше нуля,
`wait` не конечным числом от нуля, настройки `remember` без `lock`,
вызов `sweep`, забывания тега и ожидания замка внутри транзакции
и любое действие драйвера по сети (`redis`) внутри транзакции box.

## Драйверы

| Драйвер | Где живёт | Когда |
|---|---|---|
| `memory` | таблица в процессе | по умолчанию: быстро, на один узел, до перезапуска |
| `space` | спейс Tarantool | переживает перезапуск, виден репликам, значения — msgpack |
| `redis` | Redis через клиент `tnt-redis` | один кэш на все узлы и на соседние приложения; срок ведёт сервер |

### Драйвер space

`space` кладёт значения в спейс Tarantool: спейс заводится шагом
миграции, а драйвер только читает и пишет:

```lua
-- database/migrations/002_cache.lua
return function(box)
    require('tnt.cache.space').migrate(box)      -- спейсы app_cache и app_cache_tags
end
```

**Спейс по имени хранилище ищет первым обращением, а не при сборке.**
Кэш собирают при применении роли, а шаг миграции, который заводит
спейс, ядро поднимает событием уже после применения: хранилище,
искавшее спейс при сборке, на пустой базе роняло бы первое применение,
и шаг не пошёл бы никогда. Поэтому `cache.new({ driver = 'space' })`
box не трогает — его заводят и при применении, и при загрузке роли,
когда box ещё не поднят. Пока спейса нет, каждое обращение отказывает
с именем шага, а не пишет в никуда: чтение — промах с записью
в журнале, `put`, `forget` и `flush` бросают, `sweep` отдаёт пару, как
у снесённого спейса:

```
W> кэш: драйвер space отказал на чтении — промах driver=space err="кэш: спейса app_cache нет — нужен шаг миграции tnt.cache.space.migrate"
```

Найденный спейс хранилище помнит, а спейс тегов ищет, пока его нет
(ниже, «Спейс, заведённый до тегов»). Хранилище над самим спейсом
(`space = box.space.app_cache`) спейс уже держит, а спейс тегов ищет
при сборке.

Запись на реплике только для чтения отказывает, как и всякая запись
в спейс: `put`, `forget`, `add`, `increment` и `flush` бросают, `sweep`
отдаёт пару. Чтение на реплике работает, и просроченное тоже: хранилище
смотрит на `box.info.ro` и на узле только для чтения просроченную запись
не стирает — отдаёт промах и оставляет её ведущему и `sweep`. Иначе
`get` на реплике падал бы ровно тогда, когда у записи вышел срок
(проверено на 3.8: `delete` отвечает «Can't modify data on a read-only
instance»), — редкой ошибкой, зависящей от времени. Первичный индекс
спейса обязан быть TREE — шаг миграции такой и заводит.

- **Теги живут во втором спейсе `<имя>_tags`** — строка «тег, ключ»
  на каждый тег записи, первичный TREE по обоим полям. Шаг миграции
  заводит его рядом со спейсом кэша, фасад находит его по имени.
  Забывание тега выбирает строки тега куском по тысяче и стирает записи
  вместе со строками одной транзакцией на кусок; остальной кэш не
  читается. Запись помнит свои теги четвёртым полем, и перезапись
  и стирание вынимают прежние строки тегов в той же транзакции.
- **Спейс, заведённый до тегов, доводится тем же шагом**: `migrate`
  повторно безопасен — чего нет, заводит, что есть, не трогает, —
  и новая миграция с тем же вызовом дописывает пустой спейс тегов,
  а записи остаются. До доводки хранилище работает как прежде, а запись
  с тегами и забывание тега отказывают с именем шага: тег, который потом
  не забыть, не ложится. Вид `tags` у хранилища по имени заводится
  и до доводки — есть ли спейс тегов, до первого обращения не знает
  никто, — а у хранилища над самим спейсом `tags` отказывает сразу.
  После шага то же хранилище по имени пишет теги первым же обращением:
  спейс тегов оно ищет, пока его нет, и перечитывать конфигурацию
  не нужно.
- **Запись и стирание при спейсе тегов — транзакция**: прежние теги
  записи читаются и вынимаются вместе с заменой. Транзакция своя либо
  вызывающего: кэш пишут и из транзакции прикладного кода, и тогда
  запись становится её частью и откатывается вместе с ней, как одиночная
  замена.
- **Положить, если нет (`add`, замок), — вставкой.** С
  `memtx_use_mvcc_engine` чтение не видит чужой вставки, пока та пишется
  в WAL, и чтение с заменой отдало бы замок двоим: на 3.8 пять файберов
  из пяти взяли его так, а вставкой — ровно один. Вставку занятого ключа
  ядро отвергает и с MVCC, и без него; просроченное к ней хранилище
  стирает чтением.

### Драйвер redis

Клиент приходит аргументом — тот же
[`tnt-redis`](https://github.com/tnt-skein/tnt-redis), что у приложения:
пул, срок, повторы, TLS и отказ — его, и кэш соединений не заводит.
Пример прогнан на Redis 7.4 стенда (`make redis-up`); вывод — как
напечатал прогон:

```lua
local cache = require('tnt.cache')
local redis = require('tnt.redis')

local client = redis.new({ port = 16379, password = 'stand-secret', timeout = 0.5 })
local store = cache.new({ driver = 'redis', redis = client, prefix = 'demo:', ttl = 60 })

store:put('customers:7', { id = 7, name = 'Анна' })
store:get('customers:7')                                --> { id = 7, name = 'Анна' }
client:command({ 'PTTL', 'cache:demo:customers:7' })    --> 60000
store:add('lock', true, 10)                             --> true
store:add('lock', true, 10)                             --> false
store:increment('hits', 5)                              --> 5
store:pull('lock')                                      --> true
store:pull('lock', 'нет')                               --> нет
store:sweep()                                           --> { swept = 0, scanned = 0 }

store:tags('docs'):put('docs:1', 'Установка', 300)
client:command({ 'ZRANGE', 'cache:\0tag:demo:docs', 0, -1, 'WITHSCORES' })
--> { 'cache:demo:docs:1', '1790444587361' }             — миг срока в мс
store:tags('docs'):flush()                              --> 1
local lock = store:lock('reports', 30)
client:command({ 'PTTL', 'cache:demo:\0lock:reports' }) --> 30000
lock:release()                                          --> true

box.begin()
store:get('customers:7')
--> исключение: кэш: драйвер redis ходит по сети — внутри транзакции box его
--  не зовут: уступка порвёт транзакцию, а записанное в него при откате останется
box.rollback()
```

- **Ключ в Redis** — пространство `namespace` (по умолчанию `cache:`),
  приставка хранилища и ключ. `flush` стирает всё пространство обходом
  `SCAN` с образцом — кусками около тысячи ключей и одним `DEL`
  на кусок, — а не `FLUSHDB`: база бывает общей с сессиями и счётчиками
  частоты, и их `flush` не трогает.
  Знаки глоба (`*`, `?`, `[`, `]`, `\`) в пространстве берутся буквально.
  Пустое пространство — исключение при сборке: с ним `flush` стёр бы
  всю базу.
- **Значение** — msgpack в строке байтов: Redis хранит строки,
  а таблица, `int64`, `decimal`, `uuid`, `datetime` доезжают туда
  и обратно без потерь, как у драйвера `space`. Число пишется всегда
  как msgpack double: прибавку на сервере сценарий читает только так.
  Чужое под своим ключом — не msgpack либо с хвостом — читается промахом
  с записью в журнале.
- **Срок ведёт сервер** — мигом `PXAT` в миллисекундах эпохи, округлённым
  вверх. Просроченное Redis стирает сам, без обхода: `sweep` обходить
  нечего, и отчёт пуст. Живость судит один сервер — прочитанное живо, —
  иначе часы узла и часы Redis, разошедшиеся на миг, давали бы промах
  у `get` и отказ у `add` на одном ключе.
- **Одной командой — всё, что пишет по прочитанному**: `add` — `SET NX`,
  `pull` — `GETDEL`, `increment` и `decrement` — сценарий `EVAL`,
  у которого срок живой записи держится (`KEEPTTL`), а новой ставится
  по умолчанию хранилища. Между чтением и записью здесь сеть, и из двух
  команд замок `add` достался бы двоим, счётчик потерял бы прибавку,
  одноразовый знак `pull` отдался бы дважды. Двадцать прибавок из
  соседних файберов дают ровно 20 (`redis_live_test.lua`).
- **Повтор после отправки** (`idempotent`) — у чтения, записи и стирания:
  повторить их безвредно. У `SET NX`, `GETDEL` и прибавки его нет —
  повтор решил бы заново то, что сервер уже решил.
- **Внутри транзакции box — исключение**, у любого действия и до
  обращения к серверу: уступка на сети рвёт транзакцию memtx,
  и вызывающий узнал бы об этом только на фиксации, а записанное в Redis
  при откате осталось бы лежать. У чтения правило то же: бросок драйвера
  на чтении стал бы промахом, и ошибка программиста ушла бы в журнал.
- **Тег — упорядоченное множество ключей** под `namespace .. '\0tag:' ..
  тег` (тег — с приставкой хранилища). Счёт ключа — миг его срока
  в миллисекундах, у вечного — `+inf`. Запись с тегами — один сценарий
  `EVAL`: `SET` и `ZADD` во все множества разом, иначе обрыв между ними
  оставил бы значение без тега. Тот же сценарий вычищает из множества
  ключи, чей срок вышел до начала текущей секунды сервера, и ставит
  множеству срок его последнего ключа: мёртвые ключи не копятся,
  а множество уходит вместе с ними; с вечным ключом оно вечно. Нулевой
  байт в метке — затем, чтобы множество не совпало с ключом приложения:
  тег `lua` и страница `tag:lua` иначе делили бы один ключ.
- **Забывание тега — кусками одного сценария**: взять из множества
  до тысячи ключей, вынуть их оттуда и стереть. Ответ `flush` — сколько
  записей из взятых ещё было. Ключи записей сценарий знает только
  из множества и в `KEYS` их не объявляет: на одном сервере это законно,
  а Redis Cluster драйвер и так не держит.
- **Снятие замка — сценарий «стереть, если метка своя»**: из двух команд
  сосед, взявший замок после срока, лишился бы его между чтением
  и стиранием. Повтор после отправки у него есть: метку держателя
  не знает никто другой, и повтор безвреден, — но на повторе уже снятый
  замок ответит `false`.

Договор отказа тот же, что у остальных (выше): чтение при недоступном
сервере — промах и запись в журнале, запись — бросок самого отказа
`TntStorageFailure` с родом, `sent` и `retriable` — тому, кто поймает
его на границе запроса. Из прогона против закрытого порта (заголовок
ядра опущен; первую строку пишет пул `tnt-pool`):

```
W> соединение не открылось err="открыть соединение не удалось: redis 127.0.0.1:1: соединение не открылось: Connection refused" pool=redis streak=1
W> кэш: драйвер redis отказал на чтении — промах driver=redis err="соединение не получено за 0.12828736501979 с: открыть соединение не удалось: redis 127.0.0.1:1: соединение не открылось: Connection refused"
```

`pull` у `redis` — одна команда, и отказ после её отправки (`timeout`,
`broken`) мог значение уже забрать: «значение цело» из таблицы выше
держится только для отказа до отправки. Срок чтения задаёт клиент:
кэшу обычно заводят свой клиент с коротким `timeout` — промах через
полсекунды лучше ответа через пять.

Нужен Redis 6.2 и новее: `PXAT` и `GETDEL` появились в нём.

### Обход

Обход у драйверов устроен по-разному, и это видно только соседям,
которые пишут в кэш, пока идёт `sweep`:

- `space` — партии по `GT` с `limit` от последнего ключа куска.
  Ключ, дописанный соседом впереди позиции, обход увидит, позади — нет;
  стёртый впереди — пропустит;
- `memory` — снимок ключей, снятый первым куском (значения не
  копируются). Ключ, стёртый после снимка, пропускается; дописанный
  после — достанется следующему обходу;
- `redis` — обхода нет: просроченное стирает сам сервер.

### Свой драйвер

Свой драйвер — таблица с `read(key) → value, expires_at, tags`,
`write(key, value, expires_at, tags)`, `erase(key)`, `erase_many(keys)`,
`clear()`, `scan(cursor, limit) → entries, cursor` и `name`; срок `0`
значит «навсегда» либо «срок ведёт сам драйвер». `tags` — список тегов
записи с приставкой хранилища и без повторов либо пусто; драйвер,
не знающий тегов, их не получает, а `read` может их не отдавать.
`scan` отдаёт до `limit` записей `{ key, expires_at }` после курсора
и курсор продолжения — любое значение, которое драйвер поймёт
в следующем вызове; пустой курсор — обход кончился. Первый вызов
приходит с пустым курсором. Продолжать надо по уникальному ключу:
`GT` по неуникальному индексу перепрыгивает записи с тем же ключом,
что у последней прочитанной.

Драйвер, у которого между чтением и записью есть уступка, делает сам,
одним действием, то, что пишет по прочитанному: `add(key, value,
expires_at, tags) → boolean` — положить, если живого нет; `take(key) →
value, expires_at` — прочитать и стереть, для `pull`; `increment(key, by,
expires_at) → number` — прибавить, где срок — у новой записи, а пусто
в ответе — «там не число»; `erase_if(key, value) → boolean` — стереть,
если под ключом это значение, для снятия замка. Нет действия —
хранилище собирает его из чтения и записи. Драйвер, у которого чтение
не видит чужой незафиксированной записи, даёт `insert(key, value,
expires_at, tags) → boolean` — положить, только если ключа нет вовсе:
хранилище тогда стирает просроченное чтением, а кладёт вставкой.
Драйвер по сети ставит `remote = true`, и внутри транзакции box
хранилище его не зовёт.

Теги драйвер знает, если у него есть `erase_tagged(tag, limit) → taken,
erased`: стереть до `limit` записей с тегом и ответить, сколько ключей
взято из указателя тега и сколько записей из них было; взято меньше
`limit` — тег кончился. Хранилище зовёт его кусками с уступкой перед
каждым. Нет его — `tags` отказывает, а поле `tagless` говорит почему.

## Чего пакет не делает

- Не копирует значения в памяти: таблица, положенная в кэш и потом
  изменённая, изменится и в кэше.
- Не делит один драйвер по приставкам при `flush`: очищается всё —
  с тегами и замками, у `redis` — всё пространство `namespace`.
- Не продлевает замок: держатель, которому не хватило срока, берёт
  замок со сроком с запасом. Замок бережёт от одновременного счёта,
  а не от одновременного выполнения: после срока его берёт другой.
- Не будит ожидающих: они опрашивают кэш раз в 50 мс, и держатель
  на другом узле для них ничем не отличается от своего.
- Не чистит сам: `sweep` зовёт приложение — тактом
  [`tnt-loop`](https://github.com/tnt-skein/tnt-loop) или по требованию. Без него просроченное стирается по дороге, на чтении,
  и только на пишущем узле. У `redis` чистит сам сервер.

## Чем пришлось поступиться

- **Спейс с первичным индексом HASH драйвер не принимает.** У HASH
  `GT` от только что стёртого ключа отдаёт пустоту (проверено на 3.8),
  и обход обрывался бы на первом куске, чей последний ключ стёрт.
- **Снимок ключей в памяти снимается без уступки.** Это счёт по таблице
  в памяти, срез файбера его не касается, но на миллионе ключей это
  десятки миллисекунд без уступки один раз на обход. Иначе нельзя:
  `next` с ключа, стёртого до перестройки таблицы, бросает
  «invalid key to 'next'», а между кусками таблицу перестраивают соседи.
- **Отказ box посреди обхода — пара, а не откат.** Партии, стёртые
  до отказа, остаются стёртыми: обход с уступками — не транзакция.
  Просроченное ждёт следующего обхода либо стирается на чтении.
- **Просроченное на узле только для чтения не стирает ни один драйвер.**
  Признак `box.info.ro` спрашивается в хранилище, а не у драйвера:
  драйвер не говорит, переживёт ли он запись, а спрашивать его об этом
  значило бы менять договор всем, включая чужих. Кэш в памяти на реплике
  от этого держит мёртвые записи до `sweep` — читаются они всё равно как
  отсутствующие, и памяти это стоит ровно до ближайшей чистки.
- **Запись бросает, а не отдаёт пару `nil, err`.** У кэша пишут одной
  строкой посреди прикладного кода, и пару, которую там никто
  не проверит, вызывающий потеряет молча вместе с записью; бросок хотя
  бы дойдёт до границы запроса. Читающему та же строгость ни к чему — ему промах
  и нужен.
- **Чтение прячет любой бросок драйвера, а не только отказ box.**
  Отличить потерю связи от опечатки в чужом драйвере хранилищу нечем,
  а обещание «чтение не бросает» дороже: у драйвера по сети отказ —
  обычное дело. Единственный след поломки — запись в журнале, и она
  уровнем `warn`: промах кэша приложение переживает.
- **Срок у `redis` считают часы узла, а стирает сервер по своим.** Миг
  `PXAT` — это `now` хранилища плюс срок, и часы Redis, разошедшиеся
  с часами узла, сдвигают срок на то же расхождение. Остаток `PX` этого
  не знал бы, но договор драйвера — миг, а не остаток: остаток пришлось
  бы считать часами драйвера, которых хранилище не подменяет.
- **Число у `redis` — всегда double.** Целое дальше 2⁵³ теряет точность,
  как в памяти; `int64` доезжает туда и обратно, но прибавки к нему нет —
  «не число», как у драйвера в памяти.
- **`flush` у `redis` — не снимок.** Ключ, дописанный за обходом `SCAN`,
  может уцелеть; отказ посреди обхода оставляет стёртое стёртым и бросает.
- **Драйвер по сети внутри транзакции запрещён и с MVCC.** С
  `memtx_use_mvcc_engine` уступку транзакция переживает, но записанное
  в Redis при откате всё равно останется, а отличать запись от чтения
  здесь значило бы разрешить чтение, которое без MVCC рвёт транзакцию.
- **Тег у `redis` держится за ключом до срока ключа.** Ключ, стёртый
  или переписанный без тега, из множества не вынимается: для этого
  перезапись должна знать прежние теги ключа, то есть читать их лишней
  командой на каждую запись. До своего срока такой ключ лежит
  в множестве, и забывание тега сотрёт и его новое значение — лишний
  промах, а не устаревшее значение. Вечный ключ, стёртый мимо тега,
  лежит в множестве до забывания тега.
- **Значение, посчитанное до правки и положенное после забывания тега,
  переживёт забывание** и проживёт свой срок. Тег стирает то, что лежит,
  а счёт, начатый по прежним данным, кладёт своё позже; по каким данным
  считали, кэш не знает. Окно закрывает срок записи — у страниц, которые
  правят часто, он и должен быть коротким.
- **Опечатку в имени спейса видно первым обращением, а не при
  применении.** Спейс по имени хранилище ищет, когда к нему обратились:
  на пустой базе при применении роли спейса ещё нет, и отличить спейс,
  который шаг заведёт следом, от спейса с опечаткой в имени нечем.
  Хранилище с таким именем промахивается на каждом чтении с записью
  в журнале и бросает на каждой записи — с именем спейса и шага в тексте.
- **Спейсу нужен второй спейс для тегов**, а запись с тегами — это
  транзакция с чтением прежних тегов. Индекс по элементам массива в самом
  спейсе кэша был бы проще, но с `memtx_use_mvcc_engine` ядро его
  не заводит («Memtx MVCC engine does not support multikey indexes»,
  3.8), и шаг миграции падал бы на таких узлах.
- **Ожидание замка — опрос раз в 50 мс.** Ожидающий получает значение
  не позже чем через 50 мс после того, как его положили, и стоит двадцать
  коротких обращений к драйверу в секунду. Побудка была бы быстрее, но
  только для держателя на том же узле.

## Проверки

Проверки лежат в `test/` и идут на luatest: `.rocks/bin/luatest test/`.

- `cache_test.lua`, `tags_test.lua`, `lock_test.lua` — хранилище
  над драйвером в памяти и над двойником спейса: срок, приставка,
  договор отказа с записью в журнале, чистка кусками с бюджетом
  и курсором, теги, замок и счёт один раз, спейс по имени до шага
  миграции и после него. Часы — двойник, который двигает проверка;
  уступка, транзакция и спейс по имени подменяются через
  `tnt-external`.
- `series_test.lua` — ряды метрик: итог каждого обращения, одно
  обращение у `remember` с замком, длительность по подменённым часам
  и имя хранилища в метке. Ряды читаются из реестра так же, как их
  видит сборщик.
- `redis_test.lua` — драйвер `redis` над двойником клиента: какие
  команды и сценарии он шлёт и с какими настройками повтора.
- `space_live_test.lua` — драйвер `space` на настоящем box временного
  узла: шаг миграции, партии одной транзакцией, реплика только для
  чтения, теги в транзакции вызывающего, замок пяти файберам
  с `memtx_use_mvcc_engine`.
- `redis_live_test.lua` — 15 проверок против Redis 7.4 в докере: срок
  у сервера, `SET NX`, `GETDEL`, прибавка сценарием из соседних
  файберов, `SCAN` с образцом, теги и замок.

```sh
make redis-up                                  # Redis 7.4: порт 16379
.rocks/bin/luatest test/redis_live_test.lua
make redis-down
```

Без поднятого сервера живые проверки Redis пропускаются: гейты
не зависят от докера. Проверок — 123, из них 15 живых на Redis;
покрытие строк — 100 %, убитых мутантов — 100 % (474 мутанта в девяти
модулях).
