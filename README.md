# tnt-cache

Кэш приложения для Tarantool: значение по ключу на срок, теги у записей
и замок на ключ. Драйверов три — в памяти процесса, в спейсе Tarantool
и в Redis, — а договор отказа у всех один: чтение при отказе драйвера
отвечает промахом, запись бросает.

```lua
local cache = require('tnt.cache')

local store = cache.new({ driver = 'memory', prefix = 'demo:', ttl = 60 })

store:put('customers:7', { id = 7, name = 'Анна' }, 300)
store:get('customers:7')                                  --> { id = 7, name = 'Анна' }
store:remember('docs:index', 300, render, { lock = 30 })  -- считает один, прочие ждут
store:tags('docs'):put('docs:7', page, 300)               -- запись с тегом
store:tags('docs'):flush()                                --> 1
```

Зависимости: `tnt-must`, `tnt-clock`, `tnt-log`, `tnt-metrics` (ряды
обращений), `tnt-external`. Клиент Redis — `tnt-redis` — приходит
аргументом и зависимостью не объявлен.

## Зачем

Ответ, который считается дорого и меняется редко, не должен считаться
на каждый запрос. Кэшу для этого мало «положить и достать», и пакет
делает ещё четыре вещи:

- **Называет отказ у каждого действия.** Кэш — не источник правды:
  читающему промах безопасен, он пересчитает значение сам, и чтение
  при отказе драйвера отвечает промахом с записью в журнале. Пишущему —
  нет: потерянную запись не заметит никто, и запись бросает.
- **Забывает по тегу, не обходя весь кэш.** Правка одного документа
  сбрасывает все страницы раздела, где он виден: указатель «тег → ключи»
  держит сам драйвер.
- **Считает один раз.** Промах на дорогом ключе не запускает один
  и тот же пересчёт в каждом из ста пришедших разом запросов:
  `remember` с замком считает один, остальные ждут значения.
- **Показывает попадания рядами метрик.** Каждое обращение за значением
  ложится в `cache_requests_total` по хранилищу и итогу — `hit`, `miss`,
  `failed`, — а чтение драйвером — в `cache_request_duration_seconds`.

Срок, приставку, «положить, если нет», счётчик, теги и замок хранилище
считает один раз на всех драйверов, а драйвер знает только, как
прочитать, записать и стереть, — свой драйвер заводится таблицей
функций.

## Установка

```sh
tt rocks install tnt-cache --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-cache.git
cd tnt-cache && tt rocks make
```

## Как пользоваться

| Действие | Что делает |
|---|---|
| `cache.new({ name, driver, prefix, ttl, … })` | хранилище: `memory` (по умолчанию), `space`, `redis` либо свой драйвер; `name` — имя в рядах метрик |
| `get`, `has`, `put`, `add`, `pull`, `forget` | значение по ключу; срок — секунды, пусто — навсегда либо `ttl` |
| `remember(ключ, срок, счёт, { lock, wait })` | значение либо посчитанное и сохранённое; с замком считает один |
| `increment`, `decrement` | счётчик; срок записи не продлевается |
| `flush()` | стереть всё, с чужими приставками |
| `sweep({ budget, cursor })` | стереть просроченное заранее — кусками с уступкой: `{ swept, scanned }` либо `nil, err` |
| `tags(теги)` | вид хранилища: его `put`, `add`, `remember` помечают запись, `flush` забывает записи тега |
| `lock(ключ, срок, { wait })` | замок на ключ со сроком: `lock` либо `nil, err`; снимает `lock:release()` только взявший |

Спейс драйвера `space` заводится шагом миграции:

```lua
return function(box)
    require('tnt.cache.space').migrate(box)      -- спейсы app_cache и app_cache_tags
end
```

Спейс по имени хранилище ищет первым обращением, а не при сборке: кэш
заводят при применении роли, а шаг миграции идёт уже после него. До шага
чтение — промах с записью в журнале, запись бросает с именем шага.

Драйверу `redis` нужен клиент `tnt-redis`: срок ведёт сам сервер
(`PXAT`), а `add`, `pull`, `increment` и снятие замка — одна команда
либо сценарий, чтобы соседний узел не вклинился между чтением
и записью:

```lua
local client = require('tnt.redis').new({ port = 6379, timeout = 0.5 })
local store = cache.new({ driver = 'redis', redis = client, prefix = 'demo:', ttl = 60 })

store:add('lock', true, 10)                      --> true
store:add('lock', true, 10)                      --> false
```

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov, зависимости пакета, tnt-redis и tnt-env в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
make redis-up      # Redis 7.4 в докере для живых проверок; make redis-down гасит
```

Покрытие строк — 100 %, убитых мутантов — 100 % (123 проверки, из них
15 живых на Redis; 474 мутанта в девяти модулях). Драйвер `space`
проверяется на настоящем box временного узла, в том числе
с `memtx_use_mvcc_engine`; живые проверки Redis без сервера
пропускаются.
